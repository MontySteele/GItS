# "Strike the Paperwork" — Class-P protocol + purge swarm charter (DRAFT)

> **Lifecycle: LIVING while the protocol operates.** This charter does two
> things: (1) defines a standing class of items — **Class-P, paperwork** —
> that agents may resolve by recommend-and-proceed instead of queueing for
> [USER]; (2) charters a one-time swarm that purges the existing backlog
> under that authority. **Nothing here operates until [USER] signs §5.**

## §1 — The problem this solves, plainly

The queue keeps filling with questions whose answer any reasonable owner
would give the same way — fix the miscount, repoint the stale pointer,
repair the false citation. [USER] said it directly: *"a bunch of these are
either not things I needed to rule on directly, or the result of us having
too many docs still."* Routing predictable questions through a human gate
costs the gate's attention without protecting anything. The fix is not to
lower the gate for real decisions — it is to stop sending paperwork to it.

## §2 — Class-P eligibility: ALL FIVE tests, attested in writing per item

An item is Class-P only if every test passes. The attestation (one line per
test) is written before acting and lands with the change.

1. **Zero design authority.** No card behaviour, no number a player or a
   measurement feels, no player-facing text *meaning*, no law, no money.
2. **Truth-restoring or hygiene.** It corrects a false, stale, ambiguous, or
   miscounted statement, citation, pointer, name, or record — or moves paper
   to where the registry says paper lives.
3. **Reversible in one commit,** blast radius stated, bounded to
   docs/comments/metadata/tooling.
4. **The predictability test.** Would any reasonable owner ever answer
   differently? If the answer needs taste, memory of play, ecosystem
   knowledge, or a preference — it is not Class-P.
5. **No collision with a standing gate.** Not [USER]-gated by prior ruling,
   not inside an escrow, not part of a pre-registration, not inside an open
   measurement window.

**Never Class-P, regardless of the tests:** art and lore taste; naming of
content; ratification of PROPOSED numbers; mod behaviour changes; bands and
anchors; probe countersigns (pre-registrations stay [USER] by standing law);
anything where the attestation itself required a judgment call. **When in
doubt, it is not Class-P** — doubt is the signal, exactly as with child
gates elsewhere in house law: the reframing IS the answer.

## §3 — Mechanism: recommend-and-proceed with escrowed veto

- The swarm sweeps `registry/user-queue.md`, `dockets/engineering-backlog.md`
  and the REFERENCE husks for candidates; each candidate gets the five-test
  attestation.
- **Unanimous pass → proceed immediately**: land the fix with its
  attestation. **Any test in doubt → the item stays a queue row**, with the
  doubt named. Surfacing remains free; acting is what is gated.
- Every landed item gets one row in a **P-ledger**
  (`docs/registry/p-ledger.md`): what, the one-sentence predictability
  argument, the revert handle (commit).
- **Digest + objection window:** [USER] receives a one-page digest per
  batch. Any row he flags reverts by handle, no argument, no re-litigation
  — the veto is the whole consent structure, so it must stay this cheap.
  Silence after digest = ratified (this is the clause §5 authorizes).
- Lint: a P-ledger row without a five-line attestation fails the suite; a
  Class-P change touching a file owned by a [USER]-gated register fails the
  suite.

## §4 — Standing triage rule (stops future queue inflation)

From authorization forward: **before minting any new [USER] queue row, Code
applies the five tests.** Predictable items go straight to Class-P handling
and the P-ledger. The queue receives only questions that need the person —
taste, play memory, ecosystem truth, design, money. This is the durable half;
the purge below is the one-time half.

## §5 — The authorization [USER] signs (one word: AUTHORIZE / DECLINE)
