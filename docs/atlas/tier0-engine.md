# Atlas — tier0-engine

Scope: `tier0/engine/` — `combat.py`, `effects.py`, `powers.py`, `statuses.py`,
`reactions.py`, `resources.py`, `relics.py`, `potions.py`, `refpowers.py`,
`state.py`.

## 1. Purpose

This is the combat kernel of the Tier 0 Monte Carlo balance simulator: it runs
a single fight (`combat.run_fight`) over YAML-authored cards, and everything
else in the repo (harness batteries, tier05 run model, C# codegen) is either
above it or generated from it. Its job is to produce *comparable numbers* — the
whole project scores content as a ratio against `ref_ironclad/starter = 3.0`
(`tier0/README.md`, "Frozen calibration"), so the engine's first duty is not
richness but stability of the divisor. It is explicitly **not** a game: it has
no UI, no reward screen, no run layer, no draft. Combat is **emit-only** toward
the run layer — it states facts (`extra_card_screens`, post-fight heal events)
and never rolls, offers or drafts anything (`tier0/engine/state.py:606-619`,
`tier0/engine/combat.py:826-829`). It is also not a fidelity clone of StS2:
`refpowers.py:20-22` states "PARITY, NOT FIDELITY" — the real Ironclad is
scored in the same impoverished world Klee is (no relics, no potions, no events
on the battery).

## 2. Entry points

Run everything from the repo root with `PYTHONPATH=.` (the README's `.venv/bin/python`
is equivalent to `python3` here; pyyaml/pytest are already importable):

```sh
# Full battery summary for one character/deck
PYTHONPATH=. python3 -m tier0.harness.runner --character klee --deck reaction_package \
    --pilot reaction --fights 1000
# 7-axis scorecard (runs the REF_IRONCLAD baseline alongside)
PYTHONPATH=. python3 -m tier0.harness.runner --score --character klee \
    --deck demolition_package --pilot demolition
# per-fight CSV
PYTHONPATH=. python3 -m tier0.harness.runner --csv out.csv --character ref_ironclad
# whole suite / one engine area
PYTHONPATH=. python3 -m pytest tier0/tests -q
PYTHONPATH=. python3 -m pytest tier0/tests/test_combat.py tier0/tests/test_effects.py \
    tier0/tests/test_refpowers.py tier0/tests/test_reactions.py -q
```

CLI flags: `--character --deck --encounter --pilot --fights --seed --csv --score
--report-character` (`tier0/harness/runner.py:159-175`).

In-process: `combat.run_fight(player, enemies, pilot, seed) -> CombatState`
(`tier0/engine/combat.py:788`). A pilot is `(state) -> Card | None`
(`combat.py:20-21`). Test fixtures for hand-built states live in
`tier0/tests/conftest.py`.

## 3. Key invariants

- **All randomness flows through `CombatState.rng`**; nothing may import the
  global `random` functions — `state.py:4-6`.
- **Pile removal is by identity, never by value.** `Card` is a dataclass, so two
  copies compare equal; every remove goes through `remove_instance`
  (`state.py:55-69`), and the end-of-turn hand flush compares `id(c)`
  (`combat.py:571-578`).
- **Card schema is closed.** `Card.from_dict` raises on unknown fields and names
  retired ones (`fanfare_cost`) with their reason — `state.py:247-264`,
  `state.py:44-52`. Two readers share this surface: the loader and
  `tools/gen_klee_cards.py::CARD_FIELDS` (R92-3b).
- **Unknown card ops raise**, they are never skipped — `effects.py:2217-2218`.
  Gaps that cannot raise emit a loud `UNIMPLEMENTED` event instead
  (`refpowers.py:72-100`, `refpowers.py:147-149`; relics/potions do the same).
- **Damage is clamped at zero at both ends of the modifier chain**
  (`powers.py:26-45`); without it negative Strength makes an attacked player
  *gain* block.
- **Amplifier reactions (Vaporize/Melt) multiply exactly one hit and consume the
  aura — they must never persist** (`reactions.py:7-9`, consumption at
  `reactions.py:84-87`). One aura per enemy; anemo/geo trigger but never stick.
- **X-cost cards bypass every cost modifier** and spend the whole bank — the
  early return mirrors `CardEnergyCost.GetAmountToSpend` (`combat.py:124-141`).
  Spark-free is checked *before* FreeAttack/Corruption (`combat.py:171-179`).
- **Fanfare is read-only**: generated by activity, decayed each turn, never
  spent by a card (`resources.py:12-20`; no playability gate at
  `combat.py:120`). Decay runs at the true top of the player turn, before block
  clear/draw/upkeep, so it taxes inventory not income (`combat.py:419-424`,
  `resources.py:117-140`).
- **Player turn order is the StS2 site mapping A/B/C/D/E/F/G/I/M**, documented
  once in `refpowers.py:26-46` and implemented in `combat.py:411-472`. The
  load-bearing part: `refpowers.player_turn_start_late` is *after* the draw,
  while `powers.on_turn_start` is a PRE site.
- **Status cards are unplayable** (`combat.py:102-104`) and every injected copy
  is a fresh `Card` instance because pile membership is object-based
  (`statuses.py:38-41`).
- **Degeneracy is bounded** by a per-turn card cap and a hand/pile/energy state
  snapshot repeat check (`combat.py:505-518`).
- **Per-combat resource rewind uses a snapshot, not subtraction**:
  `fanfare_cap` is restored from `fanfare_cap_base` in `run_fight`
  (`combat.py:799-807`, field doc `state.py:361-374`).
- **Text I/O must declare `encoding=`** — structural gate, since the defect only
  shows on a cp1252 host (`tier0/tests/test_encoding_gate.py:1-22`).

## 4. Rulings that shaped it

- **R14** — engine diagnostics (`fanfare_turn`, `engine_closure`,
  `cards_created_this_turn`) are report-only; never acceptance targets
  (`tier0/DECISIONS.md:632`; sites `combat.py:495-533`).
- **R16** — Spotlight empowerment moved out of the relic's passive multiplier
  into cards, through the existing `spotlight_mult` pipe; `*_turn` powers are
  windows cleared at turn end, not stacks (`DECISIONS.md:386-401`;
  `powers.py:20-22`).
- **R20** — inline `upgrade:` on card rows is DEAD; `*-upgrades.yaml` is the one
  upgrade convention. The field survives only so the loader never hard-fails
  (`state.py:233-241`).
- **R33/R67** — dead-knob deletion + the KNOB_READS gate: a swept constant must
  record ≥1 real read, and knobs are served by a PEP 562 module `__getattr__`,
  so **never** write `from tier0.constants import X` (it binds at import and
  slips the hook) — `tier0/DECISIONS.md:2065-2118`, `tier0/constants.py:979-989`,
  `effects.py:298-305`.
- **R34** — X-cost cards are exempt from spark spend (a spark-freed X card would
  resolve at X=0) — `klee-mod/DECISIONS.md:963-967`; `combat.py:186-201`.
- **R36** — Crackle is damage + `discard_for_sparks`, forced discard, 1 spark per
  card actually discarded, kit cards exempt — `klee-mod/DECISIONS.md:975-990`;
  `effects.py:1474-1497`.
- **R37** — Innate: innate cards surface to the top of the shuffled draw pile
  (`klee-mod/DECISIONS.md:992-1000`; `combat.py:748`, `state.py:114-117`).
- **R39** — spark-reading effects see the bank as it was at play time, before the
  card's own spend; blast radius is exactly one card
  (`tier0/DECISIONS.md:739-760`; `combat.py:190-197`, `effects.py:516`).
- **R52** — Kokomi heals no HP: sustain is prevention + stability band; the
  healing law translates would-be heals to Block (`DECISIONS.md:1314-1340`;
  `effects.py:2259`, `effects.py:2544`).
- **R72** — bombed-state is snapshotted **at cast**, so hit 1's detonation cannot
  strip the rider from hits 2-3; a replay re-snapshots
  (`DECISIONS.md:2313-2340`; `effects.py:570`).
- **R82** — enchantments ship as a per-*instance* rider only (`enchant_damage`,
  `enchant_effects`); no registry, no subsystem
  (`DECISIONS.md:2594-2620`; `state.py:215-223`, `effects.py:2280`).
- **R85** — "Curtain Call": `register` joins the shared card schema (inert in the
  engine) and five activity-triggered powers land — deploy-block, bow payout,
  first-spend draw, first-attack draw, first-reaction — **never per-turn**, per
  the accrual law (`DECISIONS.md:2699-2750`; `state.py:134-140`,
  `resources.py:304`, `refpowers.py:729`, `reactions.py:135`).
- **R92-3b** — `tempo_band` is inert descriptive metadata on both readers, and a
  shared-schema change files its cross-session note *before* it lands
  (`DECISIONS.md:3149-3168`; `state.py:83-99`).

## 5. Traps

- **The battery is the divisor. Do not make it feel anything new.** `relics.py`,
  `potions.py` and most of `refpowers.py` are *dead branches* on the frozen
  battery, guarded by empty `Player.relic_effects` / `Player.potions`
  (`relics.py:5-16` + guards at `relics.py:86,105,184,243,259`;
  `potions.py:5-15` + `potions.py:169`). `tier0/tests/test_anchor_lock.py` pins
  the anchor's exact winrate/turns at seed 7 — it will fail loudly.
- **Frozen by ruling, not by file permission**: the encounter battery and the
  pilots' block weight (1.2) are calibrated and frozen; retuning invalidates
  every archived comparison (`tier0/README.md`, "Frozen calibration";
  `tier0/tests/test_axes.py`).
- **`refpowers.UNIMPLEMENTED` is a real exclusion list** — Stampede and
  Hellraiser are NOT approximated, and their cards must stay out of the pool
  (`refpowers.py:54-55`, `refpowers.py:72-100`).
- **Funnel granularity is an approximation with a tripwire.** Card-caused
  self-damage is observed as a delta across one CardPlay; a card with several
  distinct self-damage ops fires Inferno once and emits
  `refpower_funnel_collapse` — such a card must not enter the pool unreviewed
  (`refpowers.py:39-52`).
- **`refpowers.bind()` is a module-global seam**, not a design preference:
  `effects.py` cannot pass attacker identity, so the active state is bound in a
  try/finally around `_run_rounds` (`refpowers.py:152-171`,
  `combat.py:817-824`). A raising fight must never leak a stale state.
- **Inert-looking fields are load-bearing.** `register`, `solve`, `tempo_band`
  and `archetypes` are read by *nothing* in the engine and must stay that way —
  they exist because `from_dict` refuses unknown fields and the C# codegen
  whitelists them (`state.py:83-99`, `state.py:134-140`).
- **Two different mechanics wear the word "sly"**: Kokomi's authored `sly`
  effect list versus base-game `sly_keyword` (auto-play on discard). Both are
  handled at the one trigger site in `effects._op_discard`; unification is filed
  as tech debt (`state.py:141-163`).
- **Phase revives happen at every HP-dropping site**, always before `state.over`
  is re-read, and kill-counting predicates observe the pre-revive `hp <= 0`
  while Fatal (`counts_for_fatal`) does not — otherwise Feed farms phase-downs
  and minions for permanent max HP (`combat.py:63-99`, `state.py:427-434`).
- **`Card.__deepcopy__` is hand-rolled for speed** and copies exactly
  `_MUTABLE_FIELDS`; adding a new mutable field without adding it there shares
  state between card copies (`state.py:35-39`, `state.py:266-287`).
- **Encore absorption is credited to A4 sustain, never A3 block** — without this
  accounting rule Furina grows a phantom third elite axis (`resources.py:6-11`).

## 6. Reading order

1. `tier0/README.md` — what the sim is for, and what is frozen.
2. `tier0/engine/state.py` — the data model, the determinism contract, the card
   schema and its retired/inert fields.
3. `tier0/engine/combat.py` — `run_fight` / `_player_turn` / `_enemy_turn`: the
   ordering every other file plugs into.
4. `tier0/engine/refpowers.py` (docstring, lines 1-56) — the StS2 site mapping,
   the parity-not-fidelity stance, and the UNIMPLEMENTED list.
5. `tier0/engine/effects.py` — the card DSL: `_amount` / `_bonus_formula` /
   `_predicate` / `OPS` / `resolve_card`.
6. `tier0/DECISIONS.md` — search the R-number before changing any behaviour;
   `klee-mod/DECISIONS.md` for R34-R37 and the C# parity side.
