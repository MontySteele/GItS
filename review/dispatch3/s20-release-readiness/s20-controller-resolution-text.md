## 0. The three facts everything below hangs on

**(a) Controller mode parks the mouse cursor off-screen.** When the base game
detects a controller input it sets `IsUsingController = true`, records the real
cursor position, and warps the cursor to `(-1000, -1000)`, then hands
navigation to Godot's focus graph via `ActiveScreenContext.FocusOnDefaultControl()`
— `MegaCrit.Sts2.Core.Nodes.CommonUi.NControllerManager::CheckForControllerInput`,
decompile `MegaCrit.Sts2.Core.Nodes.CommonUi/NControllerManager.cs:332-343`, with
the off-screen constant at `:152`. Mouse input flips it back at `:315`.
**Consequence:** a Control whose only reveal path is `MouseEntered` can never
fire while a controller is in use. It is not "harder to reach"; it is
unreachable.

**(b) The base game's own creature hover is wired to BOTH signals.**
`NCreature` connects `FocusEntered`/`FocusExited` **and**
`MouseEntered`/`MouseExited` to the same `OnFocus`/`OnUnfocus` pair, and
`OnFocus` branches on `IsUsingController` to add the selection reticle —
`MegaCrit.Sts2.Core.Nodes.Combat/NCreature.cs:464-467`, `:702-707`. That
four-signal pattern is the base game's published shape for "an informational
hover that a controller can also reach."

**(c) Resolution is decoupled from layout by a fixed logical canvas.** The
window's `ContentScaleSize` is set from the aspect-ratio setting, not from the
monitor: 4:3 → **1680×1260**, 16:10 → **1920×1200**, 16:9 → **1920×1080**,
21:9 → **2580×1080**, with `ContentScaleAspect = Keep`
(`MegaCrit.Sts2.Core.Nodes/NGame.cs:774, 782, 785, 788, 791`). On `Auto` the
canvas is chosen at runtime from the measured ratio — 2580×1080 above 2.389,
1680×1260 below 1.333, else 1680×1080 with `Expand`
(`MegaCrit.Sts2.Core.Nodes.CommonUi/NGlobalUi.cs:191-210`). The resolution
dropdown itself whitelists **26 resolutions from 1024×768 to 7680×4320**
(`MegaCrit.Sts2.Core.Nodes.Screens.Settings/NResolutionDropdown.cs:209-266`).
**Consequence:** monitor pixels change how much *upscaling* happens; the aspect
setting changes the *logical box* a scene is laid out in. Those are two
different risks and the census keeps them apart.

## 5. What returns to [USER] — numbered pick lists, never blanks

These are the only decisions this file surfaces. It does not answer any of
them and does not rank the options.

**Q1. Controller support for mod-owned hover surfaces (C1, C2, C3).**
1. Support it — mod-owned hover surfaces must be reachable by controller, and
   C1/C2 are then defects to fix.
2. Do not support it — mod-owned hover surfaces are declared mouse-only, and
   C1/C2 become documented NOT-SUPPORTED rows rather than defects.
3. Defer — record the two rows, decide at the public-release gate.

## What this does NOT establish

It does not establish that controller play, any resolution, any aspect ratio,
any language, or any accessibility property is *supported* — no such promise
exists in this repo and this file invents none. It does not grade playability,
legibility, or taste. It does not confirm a single one of the six
"needs-the-game" rows by observation: nothing was launched, deployed, captured,
or measured against the running game. The Kreon result is from **upstream**
Google Fonts, not from the binary the game ships, and the two are not proven
identical. The Downfall citations describe what a public mod did; they are
reference-reading only and no code, asset, or text was copied. Finally, this is
one of seven concurrent release families — save/update, player count,
packaging, performance, colour/motion, and localization seams are covered
elsewhere and their absence here is scope, not a clean bill.
