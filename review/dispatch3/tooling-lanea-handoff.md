## 2. What was built

One original synthetic rig and one required-motion suite, compiled four ways
from a **single shared source**, then pushed through the same headless editor
`tools/build_pck.ps1` uses.

**The rig** — "Sprig", eight drawn parts (`shadow`, `leg_back`, `arm_back`,
`leg_front`, `torso`, `head`, `arm_front`, `prop`) over a nine-bone chain
(`root → hip → spine → neck` plus four limbs and a held prop). Every pixel is
generated at run time from four primitives — ellipse, capsule, rounded box,
diamond — by `tools/animation_bakeoff/art.py`. **No game, Genshin, fetched, or
licensed art is read, copied, or referenced anywhere in this lane**, and a test
asserts the art module opens no image file and contains no URL.

**The motion suite** — the five the charter requires, plus a derived `RESET`:

| motion | length | loops | what it is |
|---|---|---|---|
| `idle` | 2.4s | yes | breathing sway, prop bob, shadow pulse |
| `intent` | 0.9s | yes | the tell: prop swells and brightens, arm raises, head tilts |
| `attack` | 0.5s | no | lunge out and back, arm swing, prop throw and fade |
| `hurt` | 0.4s | no | six-key shake, red flash on torso and head |
| `death` | 1.0s | no | topple, slump, fade; prop drops and spins away |
| `RESET` | 0.001s | no | **derived** from the union of every channel any motion touches |

The motion names are the shipped ones: `CreatureAnimationRouter` maps seven
game triggers onto exactly `idle` / `attack` / `hurt` / `death`
(`klee-mod/KleeCode/Vfx/CreatureAnimationRouter.cs:45-54`), and the scene
contract (`%Visuals` → `Facing` → `Rig`, `Bounds`, `%CenterPos`, `%IntentPos`,
`%AnimationPlayer`, `%AnimationTree`) is the one the shipped Klee and Furina
scenes already satisfy (`klee-mod/pck-src/klee/model/combat.tscn:393-453`).
`intent` is the exception — see finding F6 and question Q1.

The suite is written once, in semantic channels (`offset`, `spin`, `tint`,
`swell`), and each approach compiles it into its own node paths. **264
hand-authored numbers, identical for all four approaches.** That is what makes
the source-burden column comparable at all: they are authoring the same motion.

**The four approaches**

1. **layered sprites** — one `Sprite2D` per part, tracks straight onto node
   properties. This is the shape the mod already ships.
2. **cutout / skeletal 2D** — `Skeleton2D` + `Bone2D` chain, sprites parented
   to bones, tracks onto bone rotation and position.
3. **mesh deformation** — the same skeleton, but `Polygon2D` with per-vertex
   bone weights; the torso is subdivided into five rows so hip/spine/neck
   weights genuinely bend it.
4. **particles / tweens** — one flattened billboard plus three
   `GPUParticles2D` emitters, with property tracks standing in for tweens.

### How to read the three bold rows

The suite has 27 tracks. "Expressed as written" means the approach put the
track exactly where the suite asked. "Relocated" means it had to move it to a
different node or property to work at all. "Dropped" means it could not carry
it.

- **layered** carries the whole suite with nothing moved and nothing lost. It
  is the reference, and a test pins that.
- **cutout** moves seven tracks: `Bone2D` has no `modulate` and scaling a bone
  scales everything below it, so all colour and scale channels ride the child
  `Sprite2D` instead. Nothing is lost, but the rig is no longer one place — the
  animator authors position on the bone and colour on the sprite.
- **mesh** moves six for the same reason and **drops one**: a skinned
  `Polygon2D` ignores its own `scale`, so the shadow's pulse has nowhere to go
  except the root bone, which would scale the whole figure.
- **particles** drops eighteen of twenty-seven. A single billboard has no node
  for a limb, and two per-part colour tracks collide on one `modulate`
  property. It also has to hand-author twelve numbers nothing else needs (the
  emitter toggles), so it is not as much cheaper as its node count suggests.

One texture that the scene actually references was deleted, and the pipeline

**Variant A — warm cache.** The `.png` is gone; the `.godot/imported` cache and
the `.import` sidecar survive. This is your working tree after a delete.

**Variant B — cold clone.** The `.png`, its `.import` sidecar, and the whole

Identical results for all four approaches:

| signal | variant A (warm cache) | variant B (cold clone) |
|---|---|---|
| import exit code | **0** | **0** |
| `ERROR` lines in the import log | **0** | **0** |
| scene still loads and instantiates | yes | yes |
| probe reported `ok` | yes | yes |
| probe saw a missing dependency | **no** | yes (1) |

| pack still produced | yes | yes |
| pack size (layered) | 30324 B vs 31344 B clean | 30244 B |
| pack resources (layered) | **19 vs 21** | **19 vs 21** |

Read the warm-cache column again. **A referenced texture disappeared from the
pack — two resources gone — with exit code 0 and not one error line anywhere in
the pipeline.** Nothing fails, nothing warns, and the resulting pack looks
healthy. In the cold-clone case there is exactly one diagnostic, and it is in
the **export** log.

That matters because of where the shipped producer looks. `tools/build_pck.ps1`
greps the **import** log for `ERROR` and throws
(`tools/build_pck.ps1:773-774`), but for the export it checks **only the exit
code** (`tools/build_pck.ps1:777-778`). On the evidence above, the import log is
clean in both variants and the export log carries the only signal. So a PNG
that only a `.tscn` references — not C#, so `validate.ps1` S6c's C#-reference
check does not cover it — can go missing and the build stays green.

I did **not** change `tools/build_pck.ps1`. It is a shared, single-owner file
and this lane does not own it. See patch note P1 and question Q3.

## 6. Findings

**F1 — a `.tscn` property this engine does not know is discarded silently, and
it cost me the whole mesh approach.**
My first mesh scenes wrote bone weights as `bones/0/path = NodePath(...)` /
`bones/0/weights = PackedFloat32Array(...)`. On MegaDot 4.5.1 that is **not a
settable property**: `Polygon2D.get_property_list()` exposes a single internal
`bones` entry (usage 10 = STORAGE|INTERNAL), and `PackedScene.pack` round-trips
it as a flat array, `bones = ["Root/Hip", PackedFloat32Array(…), …]`. The scene
parser dropped my lines **without an error**. Import exit 0, export exit 0,
scene loads, instantiates, animates — and `get_bone_count()` returned 0 on all
eight polygons, so nothing deformed. Verified directly against the editor, not
taken from documentation. Fixed, and the editor-side probe now reports skinned
polygon counts so the same class of silence cannot come back; a regression test
pins the spelling.
*Transfer:* any hand-written or generated `.tscn` in `klee-mod/pck-src/` can
carry a property this engine ignores and no gate will say so.

**F2 — the missing-asset gap in the shipped pck producer.** See section 5.
Evidence: `review/dispatch3/lane-a/bakeoff-results.json`, key
`approaches.*.failure_mode`. Citations: `tools/build_pck.ps1:770-778`.

**F3 — `export_filter="all_resources"` packs files nothing references.**
Measured on an earlier run of this lane that generated every art layer into
every project: the *layered* pack carried `sprig_composite.ctex` (6032 B) and
`sprig_mote.ctex` (94 B), which its scene never names. The packs also carry
`.godot/uid_cache.bin`, `.godot/global_script_class_cache.cfg`,
`project.binary`, and — until I added an exclude filter — my own
`bakeoff-manifest.json`. The mod uses the same preset
(`tools/build_pck.ps1:97`), so anything sitting in the work directory ships.
This is not a defect report against the mod: the mod's work directory is built
by explicit copy blocks. It is a constraint on any future "just drop the art in
a folder" step.

**F4 — the pack format is readable and now has a reader.**
`tools/animation_bakeoff/pck.py` reads MegaDot 4.5.1 packs (format 3): magic,
engine version, flags, `file_base`, a directory offset at byte 32, then a
count-prefixed entry list. Field layout was read out of an actual export, not
from documentation. It exists because "how big is the pack" is only half of
package cost; "what is in the pack" is the half the mod's own derived contract
cares about. It refuses a non-`GDPC` file and an unknown format rather than
reporting an empty resource list, because an empty list is exactly the reading
that makes a broken export look cheap.

**F5 — two dead rows in the shipped animation router, for spine-less rigs.**
From the decompile
(`MegaCrit.Sts2.Core.Nodes.Combat.NCreature`; scratch tree
`…/scratchpad/laneA/decomp/MegaCrit.Sts2.Core.Nodes.Combat.NCreature.decompiled.cs`):

- `NCreature::ImmediatelySetIdle` (decompile `:983-985`) calls
  `_spineAnimator?.SetTrigger("Idle")` **directly**, not through
  `SetAnimationTrigger`. Our Harmony postfix patches `SetAnimationTrigger`
  (`klee-mod/KleeCode/Vfx/CreatureAnimationRouter.cs:82-88`), so this path
  never reaches an `AnimationTree`.
- `NCreature::StartReviveAnim` (decompile `:957-963`) only emits `"Revive"`
  when `_spineAnimator != null`, and `_spineAnimator` is built solely when
  `Visuals.HasSpineAnimation` (decompile `:503-514`). For spine-less visuals —
  which is every modded character — the router's `["Revive"] = "idle"` row is
  unreachable.

Neither is currently visible, because both approach-2/3/4 and the shipped rigs
auto-return to `idle` through the state machine's at-end transitions. It is a
latent gap, not an observed bug, and it is **not mine to fix** — see Q4.

**F6 — nothing can reach an `intent` state today.** The router's table is seven
triggers onto four states (`CreatureAnimationRouter.cs:45-54`); `Cast` and
`PowerUp` both fall through to `attack`. A tell would need either a new trigger
source or a different driver. Q1.

**F7 — no Spine or paid dependency is needed, and none is proposed.** The Spine
runtime is a native GDExtension shipped with the game
(`…/Slay the Spire 2/libspine_godot.windows.template_release.x86_64.dll`), and
`NCreature.SetAnimationTrigger` is `_spineAnimator?.SetTrigger(trigger)` —
a guaranteed no-op without a spine animator (decompile `:868-871`). All four
approaches here are pure stock Godot nodes and stock `.tscn` text. **NON-FINDING
on the question "does any of this require Spine": it does not.**

- Whether a skinned `Polygon2D` rig survives BaseLib's scene-conversion

## 7. PROPOSED production grammar

**PROPOSED — a technical shape, not a recommendation to adopt anything.** Every
line below is [USER]'s to accept, amend, or discard.

1. **Layered sprites stay the default for a player character or a normal
   enemy.** It is the only approach that carried the suite with nothing moved
   and nothing lost, it is the shape already shipping, and it is the cheapest
   generator by a factor of two.
2. **Cutout/skeletal is the escalation for a body that needs limb hierarchy**
   — a long tail, a chain, a weapon that swings from a shoulder. Cost measured
   here: +10 nodes, +3.3 KB of scene, and the authoring split where position
   lives on the bone and colour lives on the sprite.
3. **Mesh deformation is a per-part decision, not a per-character one.** Only
   the torso in this rig needed subdivision; everything else rode one bone at
   weight 1. A mixed rig — meshes where something must bend, quads everywhere
   else — is what the measured numbers describe.
4. **Particles are an addition to a rig, never a substitute for one.** As a
   whole-body technique it dropped two thirds of the suite. As emitters
   attached to a layered or cutout rig it is the cheapest expression available
   for a charge, a burst, or a dissolve.
5. **Every scene declares the same contract** — `%Visuals` → `Facing` → `Rig`,
   `Bounds`, `%CenterPos`, `%IntentPos`, `%AnimationPlayer`, `%AnimationTree`,
   states `idle` / `attack` / `hurt` / `death` — regardless of technique, so
   `CreatureAnimationRouter` drives a third, fourth, and fifth rig with zero
   code changes, exactly as it drove Furina's with none.
6. **`RESET` is derived, never hand-written.** A hand-written RESET is a list
   that goes stale the first time somebody adds a track, and the symptom is a
   limb stuck where the last animation left it. Deriving it from the union of
   every channel makes the stale case impossible; that is how this lane's
   generator does it and a test asserts the coverage.
7. **Motion is authored once, in semantic channels, and compiled.** Whatever
   the technique, the times and values are the same 264 numbers. This is what
   made a fair comparison possible and it is the part most worth keeping.
8. **A generated scene is checked for node-path validity before it ships.** A
   track aimed at a node that is not there imports clean, exports clean, and
   simply never animates. The check is eight lines and it is in this lane's
   tests.

## 12. Numbered questions — where I stopped

Each is a pick list, not a blank.

**Q1 — how should an enemy's intent tell be driven?**
Nothing can reach an `intent` state today; the router maps seven game triggers
onto four states and neither `Cast` nor `PowerUp` is a tell.
&nbsp;&nbsp;(a) Leave it. Tells stay in the existing intent UI, and rigs ship
four states.
&nbsp;&nbsp;(b) Add a fifth state driven from our own C# side when an intent is
set, leaving the base game's triggers alone.
&nbsp;&nbsp;(c) Reassign an existing trigger (`PowerUp`) to `intent` instead of
`attack`.
&nbsp;&nbsp;(d) Defer until the enemy work in lane D / S18 has a real subject.

**Q2 — which technique is the default for the next rig built?**
&nbsp;&nbsp;(a) Layered sprites, escalating to cutout only when a body demands
limb hierarchy. *(This is what the measurements support; it is still your
call.)*
&nbsp;&nbsp;(b) Cutout everywhere, for a uniform authoring story.
&nbsp;&nbsp;(c) Decide per body, with no default.

**Q3 — the missing-asset gap in `tools/build_pck.ps1` (finding F2).** I did not
touch that file.
&nbsp;&nbsp;(a) Scan the **export** log for `ERROR` the same way the import log
is scanned — a two-line change, one named owner.
&nbsp;&nbsp;(b) Extend the derived contract check to `.tscn`-referenced
resources, not just C#-referenced ones.
&nbsp;&nbsp;(c) Both.
&nbsp;&nbsp;(d) Neither; accept the gap and rely on the deploy-time art gates.

**Q4 — the two dead router rows (finding F5).**
&nbsp;&nbsp;(a) Leave them. They are latent, not broken; the state machine
returns to `idle` on its own.
&nbsp;&nbsp;(b) Add a Harmony postfix on `NCreature.ImmediatelySetIdle` so a
spine-less rig hears the same reset the base game sends.
&nbsp;&nbsp;(c) Delete the unreachable `["Revive"]` row and write the reason
next to it.
