# S12e — Relic and potion hooks in public StS2 mods

*Research note, surplus-dispatch-3. Decides nothing. No design, no ids, no proposals.*

## Overview

Downfall proves relics and potions end to end, and it is the richest subsystem in
the repository: **107 relic classes across 10 characters** (9–15 each) and **15
potion classes across 5 of those 10** (exactly one Common, one Uncommon and one
Rare per character that has any). Registration is *declarative*: you subclass
BaseLib's `CustomRelicModel` / `CustomPotionModel`, tag the class (or an abstract
base) with `[Pool(typeof(SomePool))]`, and BaseLib does the rest — the pool class
itself is an empty shell. Triggers are plain `override`s of named lifecycle
methods on the base model, with a mod-local wrapper adding a `PlayerChoiceContext`
so a relic can open a co-op-safe selection screen. Rarity is a single enum value
and it is the *only* thing that decides pool membership, shop appearance and
reward eligibility — **Downfall never sets a price, never adds a shop slot, and
never writes a custom shop screen.** Rewards are the one place where real work is
required: a custom reward is a full serialize/deserialize/co-op-sync class.
Retired content is not deleted — `[Obsolete]` plus `autoAdd: false` compiles but
never registers. Art is a build-time atlas generator with a silent `todo` fallback.

## Gotchas

1. **The pool class carries no content.** `CustomRelicPoolModel.GenerateAllRelics()` returns an empty list in BaseLib itself (`BaseLib-StS2@v3.4.5:Abstracts/CustomRelicPoolModel.cs`), and every Downfall pool is a one-line `public class HermitRelicPool : DownfallRelicPool<Hermit>;` (Downfall@32e6113:`HermitCode/Core/Hermit.cs:69`). If you look for "where the relic list is written," there is no such place. Our own pools do the opposite — `KleeRelicPool` enumerates its contents by hand in `GenerateAllRelics()` (`klee-mod/KleeCode/KleeRelicPool.cs:37-48`).
2. **`[Pool]` is inherited, so a missing per-class attribute is not a bug.** All 15 Hermit relics and all 3 Hermit potions carry no attribute of their own; they inherit it from the abstract base (`HermitCode/Core/Hermit.cs:71,83`). Every other character repeats the attribute per class. Both compile; only one is a convention.
3. **Five of ten characters ship an empty custom potion pool.** Awakened, Collector, Gremlins, SlimeBoss and Snecko each point `PotionPool` at their own `CustomPotionPoolModel` subclass (e.g. `SneckoCode/Core/Snecko.cs:61,74`) but contribute zero potions. Whether the base game then falls back to vanilla potions for those characters is **not answerable from Downfall's source** — UNVERIFIED.
4. **A missing icon fails silently, not loudly.** `FallbackImg` returns a shared `todo.tres` and its warning log line is commented out (`DownfallCode/Extensions/StringExtensions.cs:174,180`). An un-arted relic looks like a finished relic with the wrong picture.
5. **Relic and potion image paths are built with `Path.Join(modId, "images", …)` — no `res://` prefix** (`StringExtensions.cs:151-154`), while scene paths in the same codebase are written `res://{ModId}/…` (`DownfallCode/Abstract/DownfallCharacterModel.cs:22-85`). Which side normalises this is UNVERIFIED from source alone.
6. **`_outline.tres` lives in the *image* atlas folder, not the outline atlas folder.** BaseLib's documented default for `PackedIconOutlinePath` is `images/atlases/relic_outline_atlas.sprites/` (BaseLib wiki, `docs/models/custom-relic.html`, retrieved 2026-08-26), but Downfall overrides the getter to point both files at `relic_atlas.sprites/` and its generator writes both there (`ImageGen/PackRelics.cs:104-107`). The override is load-bearing.
7. **Relic state is not saved unless you say so.** Only one relic in 107 uses `[SavedProperty]` (`SneckoCode/Relics/SneckoChoice.cs:32`). Everything else keeps plain private fields — `_usedThisTurn`, `_hasTriggered`, `AvailableUses` (`HermitCode/Relics/ClaspedLocket.cs:22`, `GremlinsCode/Relics/ShortStatue.cs:14-15`, `HermitCode/Relics/Shotglass.cs:23`). Those are all per-turn or per-combat, so it may never have been tested; a *run-length* counter written the same way would silently reset. (Save behaviour proper is S12f's — pointer only.)
8. **Two characters are not built by default.** `Downfall.csproj:18` lists `Downfall;Automaton;Awakened;Champ;Guardian;Hexaghost;Hermit;SlimeBoss;Snecko` — **Collector and Gremlins are excluded**, so 24 of the 107 relic classes are not in the shipped assembly. Do not read a class in the tree as shipped content.
9. **The `[Obsolete]` + `autoAdd: false` pair is the retirement idiom**, and it is not self-documenting: `GremlinsCode/Relics/StolenMerchandise.cs:7-11` is an empty class body with a rarity and a pool tag. Two `autoAdd:false` relics are *not* obsolete but unfinished stubs marked `// TODO - Event relic` (`SlimeBossCode/Relics/GreedOoze.cs:10`, `ScrapOoze.cs:10`).
10. **A model-layer restriction may still need a Harmony patch to be visible.** Shotglass caps potion use in `AfterPotionUsed`, but the Use button stays enabled until a separate postfix on `NPotionPopup.RefreshButtons` disables it (`HermitCode/Patches/ShotglassLimitPatch.cs`). Model logic and UI affordance are two jobs.
11. **A custom reward is a co-op protocol, not a screen.** `GemFinderReward` spends ~100 of its ~190 lines on `ReserveChoiceId` / `SyncLocalChoice` / `WaitForRemoteChoice` with a null-index terminator, plus in-line comments recording two fixed defects — an infinite loop when asked for more unique items than exist (`GuardianCode/Rewards/GemFinderReward.cs:64-70`) and a re-roll of an already-populated reward (`:55-57`).
12. **Pointer, not mine:** `SneckoCode/Ancients/SneckoSpirit.cs` is an ancient/event implementation (S12d), and `DownfallCode/Data/RunMetricsUploader.cs:217` rejects a run whose potions come from an unknown assembly (S12f). `Downfall.json` pins `BaseLib >= 3.4.5` while our shipped pin is **BaseLib 3.3.7.0** (`docs/current/STATE.md:159`; note `klee-mod/local.props:4` names a Workshop *dll path*, not a version, so the version lives only in that doc). S12g owns the packaging read; flagged here because every pattern above was written against 3.4.5.

## Transfer questions — against our BaseLib/Harmony abstractions

These are questions, not proposals. Each names the repo pointer that would have to be read or ruled.

1. **Do we adopt `[Pool]`-attribute registration, or keep hand-enumerated pools?** Ours is `KleeRelicPool : RelicPoolModel` overriding `GenerateAllRelics()` (`klee-mod/KleeCode/KleeRelicPool.cs:30-48`), which by-passes `CustomRelicPoolModel` entirely and therefore gets no `IsShared` and no `SeenByDefault`. Downfall's route is `CustomRelicPoolModel` + attribute. What would we lose or gain, and does `KleeSelfCheck` R7 (`klee-mod/KleeCode/Diagnostics/KleeSelfCheck.cs:136-146`) still hold under the attribute route?
2. **What does `autoAdd: false` actually leave registered?** BaseLib's ctor is `if (autoAdd) CustomContentDictionary.AddModel(GetType())` (`BaseLib-StS2@v3.4.5:Abstracts/CustomRelicModel.cs`). Our `PoundingSurprise` comment asserts "ModelDb still registers the type itself, which is all `StartingRelics` needs" (`klee-mod/KleeCode/Relics/PoundingSurprise.cs:27-30`) while also being appended by hand into `KleeRelicPool`. Which of those two is doing the work, and is one of them redundant?
3. **Is `RelicRarity.Boss` real?** `KleeRelicPool`'s header states relic rewards roll "Common/Uncommon/Rare/Shop/Boss, never Starter" (`klee-mod/KleeCode/KleeRelicPool.cs:25-28`), and our upgraded starters use `RelicRarity.Ancient` (`klee-mod/KleeCode/Relics/UpgradedStarterRelics.cs:142,281,397`). Downfall uses `Starter/Common/Uncommon/Rare/Shop/Ancient/Event` and **never** `Boss`. Which enum member names the boss tier, and does our reward-safety argument survive the answer? (S13's type inventory should settle this; do not settle it here.)
4. **Do we want potions at all, and if so whose pool?** All three of our characters currently point `PotionPool` at the vanilla `SilentPotionPool` (`klee-mod/KleeCode/Klee.cs:87`, `Furina.cs:50-51`, `Kokomi.cs:70-71`), so we ship no potion content. Downfall's answer is a per-character `CustomPotionPoolModel` with exactly three potions (one per rarity). If we ever want one Pyro potion, does that force us off `SilentPotionPool` and onto an owned pool — and does that then *remove* the Silent potions we currently inherit?
5. **Where would our relic descriptions live?** Downfall uses per-language `relics.json` / `potions.json` tables keyed `PREFIX-ID.title/.description/.flavor` (`Hermit/localization/eng/relics.json`). We use BaseLib's inline `Localization => new() { ("title", …), ("description", …) }` (`klee-mod/KleeCode/Relics/PoundingSurprise.cs:51-57`). Both are BaseLib-supported. Which one do we owe if we ever localise, and is the inline form a one-way door?
6. **Which of the 30+ trigger names do our existing kits actually need?** Downfall's distribution is heavily skewed — `BeforeHandDraw` 30 uses, `AfterCombatEnd` 14, `BeforeCombatStart` 13, everything else in single digits. Is our own relic surface reachable through the same short list, and does anything we want require the `PlayerChoiceContext` wrapper that `HookedRelicModel` exists to provide (`DownfallCode/Abstract/HookedRelicModel.cs:15-29`)?
7. **Do we need a `CustomReward` at all?** Our companion-reward slot is currently hosted on the starter relic and appends to the *existing* fight card reward (`klee-mod/KleeCode/Relics/PoundingSurprise.cs:75-80`). Downfall's `CustomReward` route (`GuardianCode/Rewards/GemFinderReward.cs`) buys a first-class reward row at the cost of a hand-written co-op sync protocol and a save serializer. Which shape does the companion slot want, and who pays the multiplayer test bill given co-op has no sim backstop?
8. **Shop: do we ever need more than a rarity?** Downfall proves that `RelicRarity.Shop` is sufficient to appear in a shop and that no mod-side pricing exists. If we ever want a priced-out or discounted item, is there a seam at all — and is that a base-engine question for S13 rather than a mod-pattern one?
9. **Do we owe a base-relic compatibility sweep?** `UnsettlingLampRegisterAllCardDebuffs` (`DownfallCode/Patches/UnsettlingLampRegisterAllCardDebuffs.cs`) exists because a *vanilla* relic mis-handled a modded card. Which vanilla relics make assumptions our aura/bomb/artifact machinery breaks, and is that a lint, a test, or a play-only question?
10. **Art contract:** Downfall's relic art is 256 px source → 85 px atlas cell + 256 px big icon + outline; potions are 64 px only, `_potion`-suffixed, no big icon (`ImageGen/PackRelics.cs:12-16`, `ImageGen/PackPotions.cs:12-19`). Ours goes through `KleePck.Path(...)` with a vanilla-slug fallback (`klee-mod/KleeCode/Relics/PoundingSurprise.cs:66-72`). Do our sizes match, and is a silent `todo` fallback (gotcha 4) acceptable to us or exactly the thing `art_lint` should bite?

## NON-FINDINGS

Each of these was looked for and is genuinely absent from the primary sources searched — absence is the result, not a gap in the reading.

- **No shop pricing of any kind.** No `Price`, `Cost`, `GoldCost` or discount member on any relic or potion in Downfall; a full-tree case-insensitive search for `price|shop|merchant|GoldCost` returns only `RelicRarity.Shop` declarations, the merchant *animation* node classes (`DownfallCode/Vfx/NSpineMerchantCharacter.cs`), and one card-side hook (`SneckoCode/Relics/UnidentifiedEgg.cs:48`).
- **No custom shop screen, shop stock slot, or shop-inventory composition.** The only shop-screen contact is a cosmetic merchant character (`DownfallCode/Abstract/DownfallCharacterModel.cs:85`, and BaseLib's wiki page "Merchant Character Visuals").
- **No potion capacity / potion-belt / slot-count change.** Nothing in the tree touches potion slots. (`GuardianCmd.RemoveMaxStasisSlots` and `SlimeBossCmd.DecreaseSlots` are character-mechanic slots, not potion slots.)
- **No potion outside `PotionUsage.CombatOnly`.** All 15 use it; no out-of-combat or map-screen potion exists to copy a pattern from.
- **No relic Artist attribution.** Artist hover tips exist for cards and potions only; zero relic files mention `Artist`.
- **No custom relic *reward* screen.** Both `CustomReward` subclasses in the tree deal in cards/gems/collectibles; the only relic-granting route implemented is `RelicCmd.Obtain` from an event option (`SneckoCode/Ancients/SneckoSpirit.cs:80`).
- **No boss-relic pool or act-gated relic pool.** `RelicRarity.Ancient` relics exist but nothing in Downfall selects or restricts them per act.
- **BaseLib publishes no `CustomPotionModel` documentation page.** Its wiki has model pages for Act, Ancient, Card, Character, Encounter, Event, Orb, Relic, Singleton and TemporaryPower — and none for potions (`https://alchyr.github.io/BaseLib-Wiki/`, retrieved 2026-08-26). The potion contract is source-only.
- **No relic/potion migration or id-stability machinery** in Downfall (that question is S12f's; the search here found nothing on my side of the line either).
