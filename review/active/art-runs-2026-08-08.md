## The rank-2 rule this pass runs on

`art_process` promotes **rank 1** of a shortlist to the final out-path as a
provisional pick. So every row this pass added is **rank ≥ 2 by design** — that
is what lets a candidate set land without making a pick. Two consequences worth
stating, because both are load-bearing:

- `grand_gala`, `spotlight_center_stage`, `spotlight_guest_cast` and
  `confiscated` still render placeholders and `art_coverage` still bills them
  missing (4). That is correct: the hunt is done, the pick is not.
- the seven `furina/powers/*.png` sigils still have **no file**, which keeps
  `validate.ps1` S12's `$pckDeferred` entries honest. A rank-1 row there would
  have shipped art into a deferred path and failed the deploy gate.

Do not renumber any row below to rank 1 without a ruling.

### 10 — `EB-88`, and two corrections to its own brief

Producer: **`tools/gen_energy_orb_layers.py`** (tracked). Three sets ×
five 256×256 layers, each with a composed preview and an **Energy-0 darkened**
preview, in `art/candidates/furina_energy_orb/set_{a_fontaine,b_opera,c_tidal}/`.

**Generated, not hunted, and that is the honest route rather than a shortcut.**
An orb layer is a UI texture — glow, body, caustic, bezel, gloss. The wiki pool
has no such register: a Hydro hunt returns 128–512px element sigils, which is
the dead `vfx` register the Kokomi pass already documented. A fetched sigil
dressed as a layer set would have been a fake set, and the brief for this run
said a documented zero beats one of those. Nothing writes to an `ImageGen/`
out-path and there is no `art/plan.tsv` row, so `art_process` **cannot** promote
any of it.

| set | read |
|---|---|
| **A — Fontaine Hydro** | Deep-blue vitreous sphere, thin bright bezel. Closest in construction to the base game's own orb, so it is the set that will look least like a mod. |
| **B — Opera Pale** | Furina's own palette rather than the element's: pale ice-blue and white, a petal-cut rotation ring. Reads theatrical, and reads **weakest when darkened** — the Energy-0 tile on the sheet is where to check that. |
| **C — Tidal** | Saturated teal, heavy caustic, doubled ring. Most legible at a glance, furthest from the base game's colour language; it will not sit quietly next to Klee's counter. |

Two facts read out of the shipped assembly (`ilspycmd -t
MegaCrit.Sts2.Core.Nodes.Combat.NEnergyCounter`, 2026-08-13) **correct the brief
that `M19`, `EB-88` and `EB-40` all carried**:

1. **`energy_orb_dark.tres` is the darkening material applied when Energy == 0,
   not the container the five textures live *under*.** `AssetPaths` lists that
   material and nothing else, because the textures belong to the *scene*. The
   "five" is the base scene's authoring choice, not a code constraint — both
   loops are `GetChildren()`.
2. **There are two stacks, not one.** `%RotationLayers` children are spun by
   `_Process` at `delta · num · (i + 1)` degrees (`num` = 30 normally, 5 at
   Energy 0), so a rotation layer must be **centred** and must read **while
   tumbling** — an art constraint nobody had written down. And at Energy 0
   *both* stacks take the dark material while `%Layers` is additionally
   `Modulate`d `DarkGray`, so a layer that only reads at full saturation is a
   defect that appears on empty turns only.

**What could not be read, and is labelled as inference on the sheet:** the base
scene itself. `SlayTheSpire2.pck` is `GDPC` pack format 3 with
`pack_flags = 2` (PACK_DIR_ENCRYPTED), verified directly — the file directory is
encrypted, so `ironclad_energy_counter.tscn` and its five textures are not
readable off disk without the game's key. The layer **roles** are therefore
derived from the class contract, and **256×256** is a production choice with
headroom over the shipped 74px icon, not a measured size. Both are stated as
inferences on the sheet rather than presented as reads.
