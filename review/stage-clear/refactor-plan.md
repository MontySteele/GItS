### Proposed split

- `tier0/DECISIONS-archive-R39-R99.md` — verbatim freeze of R39–R99 (the
  pre-Surplus-week closed range; R100+ is the currently-cited working set:
  R101b strike law, R107–R120 all actively referenced this wave). Banner at
  top of the archive volume and a stub note at the cut point in the live file.
- `tier0/DECISIONS.md` keeps: prose preamble, R100–current, and a
  **generated current-law digest** block (below).
- `klee-mod/DECISIONS.md` — **recommend NO split this pass.** It is half the
  size, its R-range (R73–R80) is one closed batch, but its still-operative
  prose entries (E2/E2b, corpse detonation, the fork block with dated [USER]
  annotations) are interleaved with history; a split would need per-entry
  operative judgments that are exactly the "attestation required a judgment
  call" class. Revisit after S4-G13/S4-G15 close.

### Still-operative rulings → the digest

"Operative" cannot be derived mechanically from prose (a struck banner is
detectable; partial supersession is not). Proposal: a **sidecar status table**
`tier0/decisions-status.tsv` (`R-number → OPERATIVE | SUPERSEDED-BY:R<n> |
DISCHARGED | HISTORICAL`, one row per R39+ ruling, append-style, judgment
recorded once and lint-checked for completeness against the ledger's heading
set). The digest generator then has no judgment in it:

- **Tool spec — `tools/gen_decisions_digest.py`:** inputs = all
  `DECISIONS*.md` volumes + the sidecar; output = a `<!-- GENERATED -->`
  fenced digest block (one line per OPERATIVE ruling: number, date, first
  sentence of its heading/lede, volume#anchor). Modes: `--write` (rewrite the
  block in place), `--check` (CI: fail if block is stale, byte-diff). Never
  hand-edited — the block carries the generator's name and a do-not-edit
  marker, same regime as `known-identifiers.tsv`.
- Initial population of the sidecar is the one judgment-bearing step: it is a
  paper pass with per-ruling one-line rationales, delivered for [USER]
  red-pen before the generator's output is ever quoted (the sidecar is where
  a wrong "operative" call would live, so it gets the eyes-on once).
